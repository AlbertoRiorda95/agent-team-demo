## What changed
The web app now has client-side routes `/login` and `/` (inside an app shell
that needs a session), a new user flow (login, 401 → `/login?next=<path>`,
Log out) and the `react-router` dependency.

## What the others relied on (before → after)
- Route (devops): `/` served the health panel directly → `/login` and `/` are
  client routes; the web server must serve `index.html` for any path that is
  not a file, `/api` or `/health` (history fallback). `apps/web/nginx.conf` is
  devops' file: check that `try_files ... /index.html` is there.
- Flow (backend, designer): the web app calls `GET /auth/me` on load and
  `POST /auth/login`, `POST /auth/logout` with same-origin JSON through
  `/api/v1`; any 401 of a staff request sends the user to login.
- Contract: no change; `schema.d.ts` regenerated (adds the 403 of the
  previous task).
