## What changed
`POST /api/v1/orders` is implemented (order-intake, task 1/3). It needs a new
environment variable, `ORDER_API_KEY`. The contract gains a 413 response and a
`quantity` maximum. Three new tables and one sequence are added: `orders`,
`order_lines`, `status_changes` and `order_number_seq`.

## What the others relied on (before → after)
- **Environment variable (devops):** none → `ORDER_API_KEY`, at least 32
  characters. It is required when `NODE_ENV=production`, and the service will
  not start without it there. Outside production it may be unset: the service
  logs a warning and `POST /api/v1/orders` answers 401 to every request. It is
  never logged and never echoed in errors. It belongs in `.env.example`
  (placeholder only), `compose.yml` and the CI orders job (spec task 3,
  `docs/design/order-intake.md`). The orders tests do not need it: they pass
  their own test key.
- **Contract (frontend):** `POST /orders` gains a `413` response
  (`PayloadTooLarge`, problem+json, body above 256 KB).
  `OrderLineInput.quantity` gains `maximum: 10000`. The `Amount` description
  now says responses always carry the currency's minor digits. All of this is
  additive, and the web app does not call `POST /orders`. Regenerating
  `schema.d.ts` (`npm run gen:api -w apps/web`) picks it up; no code change is
  expected.
- **Data model (backend M2, designer):** new tables `orders` (amounts as
  bigint minor units, unique `external_reference` and `number`,
  `(status, created_at desc)` index), `order_lines` (`position` from 0) and
  `status_changes` (empty, FK to `orders` and `staff_users`). New sequence
  `order_number_seq`. The migration is additive (`0002_order_intake.sql`), with
  rollback notes in its header.
